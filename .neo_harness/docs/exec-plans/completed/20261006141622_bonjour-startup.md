# App 啟動時修復 Bonjour Service

## 目的

讓一般 App 啟動流程檢查 Bonjour Service。服務停止、路徑不符或服務項目不存在時，若有符合現有信任條件的 Bonjour 檔案，透過 UAC 將服務修復或安裝並啟動；若找不到來源，提供 Apple 官方安裝資訊。

## 背景與行為

- 目前 `App.xaml.cs` 只在投影引擎套件準備成功後檢查 Bonjour；引擎準備提前失敗時不會嘗試 Bonjour。
- `BonjourServiceInspector` 從服務 ImagePath 或 ProgramData 備份找可信任檔案；找不到服務且沒有備份時沒有來源發現路徑。
- `Stage-BonjourRuntime.ps1` 與 `Install-BonjourService.ps1` 都要求 Bonjour Service 已存在；安裝腳本只會切換既有服務路徑。
- 還原腳本假設備份一定包含原 ImagePath，無法還原「原先沒有服務」的狀態。

## 限制與決策

- 不下載或散布 Bonjour 執行檔；只使用 64 位元 Program Files 下通過產品資訊及版本一致性檢查的本機檔案。
- 有本機來源時，Elevated helper 將檔案 staging 到受保護共用目錄；缺少服務項目時，以 mDNSResponder 的 `-install` 建立並啟動服務。
- Bonjour 操作只顯示簡短原因後觸發 UAC，不再顯示額外 Yes/No；拒絕、停用或失敗時回報狀態，不自動變更既有服務的 Disabled 啟動設定。
- 找不到來源時沿用 Apple 官方安裝說明；Android 不受 Bonjour 狀態影響。
- E2E profile 不執行系統服務操作；`--start` 只有在引擎與 Bonjour 都就緒時才啟動 AirPlay。
- ProgramData 的預設 ACL 含有可繼承的 Users Write 權限；備份目錄需移除繼承並改為一般使用者唯讀，避免服務存在狀態遭竄改。
- 還原「原先沒有服務」時，必須確認目前 ImagePath 仍指向 Neo AirPlay 共用執行檔，才可移除服務。

## 工作順序

1. 擴充 Bonjour 來源檢查，識別服務缺失與停用狀態。
2. 更新 staging、安裝與還原腳本，支援建立新服務並可還原至原本未安裝狀態。
3. 抽出可測試的 App Bonjour 啟動協調流程；確保 Bonjour 檢查不被引擎套件失敗略過。
4. 新增啟動流程單元測試，更新 README 與 Harness 架構、安全、復原文件及命令索引。
5. 執行 Harness 驗證並檢視差異。

## 復原方式

程式碼變更可由 Git 回復。目標機器若需還原服務，執行更新後的 `scripts/Restore-BonjourService.ps1`；服務原先不存在時，該腳本會移除 Neo AirPlay 建立的 Bonjour Service。共用目錄檔案保留供下次啟動重試。

## 結果

已完成程式碼、文件與自動驗證。未在目前 Windows 環境實際安裝、啟動或移除 Bonjour Service，因該驗收會修改系統服務狀態；需在有可信任 Bonjour 安裝檔的測試 Windows 上執行端到端服務驗收。
