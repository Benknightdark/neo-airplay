# 統一 Node.js 24 與 CI 工具路徑

## 目的與背景

CI 的驗證入口會重排工具路徑，覆蓋工作流程選定的 Node.js，並因舊的 Node.js 22 限制而失敗。已使用隔離假工具重現。使用者指定遷移至 Node.js 24。

## 目前與預期行為

目前固定版本為 22.23.3，套件及驗證入口要求 22.x。預期統一固定為 24.22.2，接受至少 24.22.2 的 24.x；當 `NEO_AIRPLAY_SKIP_SETUP=1` 時，驗證入口及 Tauri 子程序沿用呼叫端工具路徑。

## 限制與決策

- 沿用既有 CI/CD 的版本檔設定，保留 Bun 與 Rust 版本。
- 本機環境準備及已完成準備的啟動流程維持原有工具優先順序。
- 六個安裝封裝的 SHA-256 依官方校驗清單更新，維持下載驗證。
- 測試專案的直接 Node.js 型別依賴更新至 24.x；保留其他相依套件的版本要求。

## 工作順序與具體步驟

1. 更新版本檔、套件要求、驗證及啟動入口、安裝校驗值。
2. 更新假工具測試並新增版本邊界與路徑優先順序回歸案例。
3. 更新測試鎖檔與 README，記錄略過準備時的路徑行為。
4. 在隔離 Node.js 24 環境執行完整驗證、可用的平台建置及桌面測試。
5. 審查所有變更，記錄結果與平台驗證缺口，移至完成目錄。

## 進度與發現

- 已確認 CI/CD 都從版本檔安裝 Node.js。
- 已確認 Tauri runner 也會重排路徑，需與驗證入口一起修正。
- 已將本機 `~/.local/lib/neo-airplay/node-v24.22.2` 與 `~/.local/bin` 符號連結更新為官方 SHA-256 驗證通過的 Node.js `24.22.2`。
- 修正 `verify.ps1` 與 `test-setup.mjs` 在非 Windows 主機的 `pwsh` 下大小寫敏感 `PATH`/`Path`、`$PSHome` 前綴及 `runTauri` 測試 `spawn` 參數記錄問題。
- 已完成 macOS 完整驗證、PowerShell 驗證入口與桌面 E2E 測試。

## 驗證

- 隔離測試涵蓋 Node.js 24 成功、22 與 26 被拒絕，以及最低版本邊界（`24.22.1` 被拒絕、`24.22.2` 通過）。
- 回歸測試涵蓋略過準備（`NEO_AIRPLAY_SKIP_SETUP=1`）時保留呼叫端路徑及正常本機準備流程（`verify.sh`、`verify.ps1`、`run-tauri.mjs`）。
- 已執行 `bash desktop/scripts/verify.sh`（通過：前端與測試型別檢查、28 項前端單元測試、44 項安裝與路徑測試、6 項版本工具測試、Rust fmt、33 項 Rust 後端單元測試、Clippy、Vite 建置）。
- 已執行 `pwsh desktop/scripts/verify.ps1`（通過）。

## 復原方式

以本次變更差異為界復原 Node.js 版本、套件鎖檔、腳本及文件；本機 `~/.local/bin/{node,npm,npx}` 可切回 `~/.local/lib/neo-airplay/node-v22.23.3/bin/`。

## 結果

已完成。專案與測試固定使用 Node.js `24.22.2`（接受 `>=24.22.2 <25.0.0`），且在 `NEO_AIRPLAY_SKIP_SETUP=1` 時 `verify.sh`、`verify.ps1` 與 `run-tauri.mjs` 均保留呼叫端工具路徑，不再覆蓋 CI 選定的 Node.js 版本。
