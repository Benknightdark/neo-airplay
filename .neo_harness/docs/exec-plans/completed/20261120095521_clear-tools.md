# 「清除工具」功能執行計畫

## 目的與背景

目前 `ToolManagementPage.vue` 在 `.tool-action-grid` 僅提供「升級工具（`upgrade`）」與「清除並重新安裝（`reinstall`）」兩項全域維護動作。若使用者希望先徹底清除先前透過 Neo AirPlay 安裝的所有投影工具與快取（但不立即重新安裝），需要一個獨立且安全的「清除工具」入口。

## 目前與預期行為

- **修改前**：
  - `DependencyAction` 與 `DependencyOperation` 僅支援 `Upgrade` 與 `Reinstall`。
  - `ToolManagementPage.vue` 的 `.tool-action-grid` 僅有「升級工具」與「清除並重新安裝」兩張卡片。
- **修改後**：
  - 前後端領域與應用層擴充 `clear`／`Clear` 動作；觸發前同樣經由 `stop_engines_for_maintenance` 先停止 AirPlay 與 Android 投影引擎。
  - 後端執行 `stop_adb_server_if_present`、`clear_app_tools`（清空 `engine/` 可重建檔案並保留 `.GITKEEP`、`.bundled-*`，並刪除 macOS GStreamer registry）、`reset_tool_version_preferences`（移除 `tool-versions.json`）及 `clear_transient_setup_files`（清除 `install.pid`、`install-result.json`、`install-launch.json`、`install-progress.json`、`launch.sh` 並保留 `install.log`），隨後寫入安裝記錄並透過 `check_runtime` 驗證清理結果，將狀態設為 `failed`（介面顯示「需要處理」）與 `missing` 清單。
  - 保留系統套件管理器套件、接收器設定 `settings.json` 與安裝／診斷日誌。
  - 前端 `ToolManagementPage.vue` 新增並列第 3 張「清除工具」卡片與二次確認對話框，狀態卡並於 `failed` 時提供「重新檢查並安裝」入口；工具目錄自動刷新顯示「尚未偵測」。

## 限制與決策

- **清理邊界**：僅清除 App 專用目錄、快取、過渡性 `setup` 標記與 `tool-versions.json`，不動系統層級套件管理器（Homebrew / MSYS2 / APT / DNF / Pacman），避免誤刪共用依賴或要求系統提權。
- **清除後恢復**：清除後狀態轉為 `failed`，保留「重新檢查並安裝」、單工具安裝與重開 App 自動檢查補裝行為。
- **Clean Architecture**：維持前後端向內依賴規則，無需新增 Tauri IPC 命令或變更 capability 權限。

## 工作步驟

1. 擴充後端領域層（`domain/dependency.rs`）與應用／表現層文件（`ports.rs`、`presentation/commands.rs`）。
2. 實作後端基礎設施層清除流程（`infrastructure/dependencies.rs`），含 ADB server 預先結束、過渡性標記安全清理與 `check_runtime` 驗證。
3. 擴充前端領域、應用、閘道與 Composables（`domain/dependency.ts`、`useToolCatalog.ts` 等），並於 `ToolManagementPage.vue` 新增第 3 張「清除工具」卡片、二次確認對話框及狀態卡恢復入口。
4. 補齊前後端單元測試與桌面 E2E 斷言，更新 `README.md`、`.neo_harness/RELIABILITY.md` 與 `.neo_harness/SECURITY.md`。
5. 執行 `bash desktop/scripts/verify.sh` 與 `cd desktop-test && bun run --silent test:e2e:ci` 驗證，完成後將本計畫移至 `completed/`。
