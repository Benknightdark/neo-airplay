# Android 投影與雙平台驗證

## 目的

在現有 Windows 11 x64 WPF 接收器加入 Android 畫面與音訊投影，參考 Genymobile/scrcpy 的官方 Windows 執行方式；保持既有 UxPlay AirPlay 功能可用，並補足 Framework 單元測試及 App UI E2E。

## 背景與目前行為

- App 目前只組裝 `UxPlayProcessEngine`，透過 UxPlay 接收 AirPlay；播放畫面由外部引擎視窗顯示。
- `IReceiverEngine`、UxPlay 程序監督及 Bonjour/GStreamer 的依賴已分離；不應把 Android ADB 細節塞入 UxPlay。
- UI E2E 驗證 WPF 導覽與 Android 控制項；HardwareE2E 另有一項啟動實際 WPF App、操作 Dashboard 並連接授權 USB 手機的測試。
- `.neo_harness/verify.ps1` 是修改後必要的建置與 Unit 驗證；UI E2E 需另行執行。
- 官方 scrcpy 文件稱 Windows 發行包同時提供 scrcpy 與 ADB。Android 最低支援 API 21；音訊轉送需 API 30 以上；裝置需啟用 USB 偵錯。可用 USB 或 TCP/IP。使用者已選擇 USB 與「已配對 Wi-Fi」；完整無線配對流程不屬於目前範圍。
- 依官方 Windows 文件，鎖定 scrcpy v4.1 x64 發行包，預期 SHA-256 `5b12172b3264b2889f4583ee64752ce832e29bc8b1089dca81093459697165db`；只從 Genymobile 官方 GitHub 下載。上線前還須確認解壓結構、隨附授權文字及 Android 音訊行為。
- 使用者確認 iOS 與 Android 必須同時投影；因此兩個引擎、狀態與啟停控制獨立，不能做成互斥的單一來源選單。

## 預期行為

- Apple 裝置仍使用原 UxPlay/AirPlay 接收程序與 Bonjour/GStreamer 執行環境；該程序可以在 Android scrcpy 運行期間繼續接收。
- Android 裝置使用 scrcpy 官方 Windows 客戶端與 ADB；列出已連線裝置、清楚顯示未授權/離線狀態，並可選擇裝置開始/停止投影。
- ADB 的 USB 與已配對 TCP/IP 裝置使用同一個裝置清單流程；不假設或自動執行無線配對。
- Android 裝置選擇、程序生命週期、缺少相依檔、程序錯誤與裝置中斷都需有可讀狀態及診斷記錄。
- 單元測試涵蓋 ADB 裝置列解析、共用必要檔案清單、scrcpy 參數、啟停/程序提前結束、裝置刷新失敗時保留執行中投影狀態等情境；UI E2E 驗證 Android 控制存在與可操作、頁面導覽正常；HardwareE2E 操作真實 USB 裝置，不偽稱驗證了 iOS 或無線影音傳輸。

## 限制與未知事項

- 本次已用 USB 授權 Android 裝置跑通 scrcpy 可見視窗與 UxPlay 並行；已配對 TCP/IP Android 裝置尚未實機測試。
- HardwareE2E 驗證真實 Android 裝置、scrcpy 視窗及兩個接收程序並行，但不檢查視窗像素或實際音訊輸出。
- iPhone/iPad 的 AirPlay 真實投影由使用者自行測試；本次只確認 UxPlay 可啟動並同時與 Android 引擎執行。
- App UI E2E 需在互動式 Windows 桌面工作階段執行；本次已在此桌面通過。
- 本機 Bonjour 元件不可公開散布，任何輸出打包變更必須保留既有授權限制。
- scrcpy 執行檔和 ADB 應由可重現的官方來源 staging 到被忽略的 `engine/` 目錄，不直接提交生成的二進位輸出；公開發佈仍須附上所需授權/通知。

## 工作順序

1. 核對官方 scrcpy v4.1 Windows zip 的雜湊、內容、啟動參數與授權；確認目前主機是否有 ADB/Android 裝置。
2. 設計 Framework Android 裝置資訊、ADB 查詢與 scrcpy 程序生命週期介面，使用可替換程序/命令執行邊界。
3. 新增官方 scrcpy/ADB staging 腳本並納入現有引擎建置/發佈流程；不更動 Bonjour 服務管理行為。
4. 在 App 加入 Android 裝置刷新、選取、開始/停止與診斷狀態；iOS AirPlay 控制與設定維持正確。
5. 增加 Framework Unit 測試、App ViewModel Unit 測試與 UI E2E 覆蓋。
6. 更新 README、架構/可靠性/安全文件與命令清單；執行 `.neo_harness/verify.ps1`、App UI E2E、硬體並行 E2E 及 Release 發佈檔案檢查。
7. 逐項記錄驗證結果與尚未能在本機證明的行為；iOS 實機投影與 Android 已配對 Wi-Fi 由使用者補做驗證。

## 驗證命令

- `.\scripts\Stage-ScrcpyRuntime.ps1`（預計新增，官方封存檔下載、SHA-256 核對及 staging）
- `.\.neo_harness\verify.ps1`
- `dotnet test tests/NeoAirPlay.App.Test/NeoAirPlay.App.Test.csproj --filter "Category=E2E"`
- `dotnet test tests/NeoAirPlay.App.Test/NeoAirPlay.App.Test.csproj --filter "Category=HardwareE2E"`
- `dotnet publish src/NeoAirPlay.App/NeoAirPlay.App.csproj -c Release -o dist/NeoAirPlay-Release`
- 人工實機：iPhone/iPad 與 Windows 在同一 LAN，透過 AirPlay 控制中心選取 Neo AirPlay 並確認畫面/音訊；如要驗證 Wi-Fi，也需以已配對 TCP/IP Android 裝置再測一次。

## 復原方式

- 新增 Android UI/服務可獨立移除，保留 `UxPlayProcessEngine` 原服務與既有設定資料格式。
- 若官方封存檔、授權或實機行為不符預期，停止 staging，移除 Android staging 入口和 Android UI/服務；不要更動 Bonjour 安裝或還原系統服務。
- 發佈輸出為可重建的 `dist/` 產物；可刪除並重新執行 publish。
